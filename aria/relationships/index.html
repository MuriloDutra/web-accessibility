WAI-ARIA

Relationships

Some relationships are not parent and child in the HTML. These attributes tell the accessibility tree how the pieces connect.

aria-owns

aria-owns lists elements that should be children in the accessibility tree, even when they sit somewhere else in the DOM. The value is one or more ids, in the order a screen reader should meet them.

A screen reader meets Apple and Bread inside Snacks. In the HTML, those two items are not inside #snacks.

Note: Nest the elements in the DOM when you can. aria-owns is for a relationship the markup cannot show, such as a menu drawn in another part of the page.

aria-activedescendant

aria-activedescendant points at the option that should be treated as focused, while keyboard focus stays on the ancestor. A screen reader announces that option. Tab still lands on the list once.

Note: Arrow keys move the highlight. Focus stays on the list. The script updates aria-activedescendant. The attribute alone does not move a highlight.

Focus is on the list. With aria-activedescendant="lesson-focus", a screen reader treats Focus as the current option. The same idea keeps a combobox focused in its text field while the highlighted choice is read aloud.

aria-posinset and aria-setsize

These two go on each item. aria-posinset is that item’s place in the full set. aria-setsize is how many items the set has. Use them when the page only holds a slice, such as a long list that loads rows as you scroll.

Result 857
Result 858
<div role="listbox" aria-label="Search results">
    <div role="option" aria-posinset="857" aria-setsize="1000">Result 857</div>
    <div role="option" aria-posinset="858" aria-setsize="1000">Result 858</div>
</div>

Only two rows are in the page. A screen reader can still say “857 of 1000” and “858 of 1000”.

Note: Put both attributes on the item, not on the list. When every item is already in the DOM, the browser can count the set and these attributes can stay off.
