WAI-ARIA

Labels

The name is what a screen reader calls the control. A description is extra detail that comes after that name. These three attributes set those two pieces.

aria-label

aria-label writes the name onto the element. Use it when the visible content is a symbol, or a word that does not say what the control does.

Name: “X”

Name: “Close”

<button>X</button>
<button aria-label="Close">X</button>

The first button is announced “X, button”. The second is announced “Close, button”. Close is the name in the accessibility tree. The X stays on screen.

Note: aria-label replaces the text inside the element as the name. It does not add visible words.

aria-labelledby

aria-labelledby points at text that is already on the page. The name is that text. You can list more than one id, and the browser joins them in that order.

Email

<p id="email-label">Email</p>
<input type="email" aria-labelledby="email-label">

A screen reader says “Email” for that field, because the name comes from #email-label.

Note: Clicking “Email” does not focus the field. A <label for> does both: it names the control and moves focus there. Use aria-labelledby when the text already lives somewhere else, such as a heading that names a group.

aria-describedby

aria-describedby points at extra help. That text is the description, after the name. The name still comes from the <label>.

At least 8 characters, with a number.

<label for="password">Password</label>
<input id="password" type="password" aria-describedby="password-hint">
<p id="password-hint">At least 8 characters, with a number.</p>

A screen reader says “Password”, then “At least 8 characters, with a number.” Password is the name. The hint is the description.

Note: Keep the name short. Put rules, errors, and other help in aria-describedby.

Which name wins

When more than one name is available, the browser uses the first match in this order:

  1. aria-labelledby
  2. aria-label
  3. A <label>, or the text inside the element
