Semantics

Screen Readers

Using the HTML tags correctly helps screen readers understand the content of the page and navigate through it. A few examples:

<button> vs <div>

By using a button tag you facilitate the interpretation of the page for screen readers. The user listening to the page will know that the button is clickable

Note: This is also helpful for keyboard users because they can focus on the button using only the keyboard.

<button>Click me</button>
<div role="button">Click me</div>

<img> alt attribute

The alt attribute is used to provide a text description of the image. This helps screen readers understand the image and its purpose.

Note: A good exercise is to purposefully fail to load all the images on the page and see if only with the alt/alternate texts you can still understand what the page is about.

<img src="image.jpg" alt="A description of the image">
<img src="image.jpg" alt="">

Label + Input

The label tag is used to provide a text description of the input. This helps screen readers understand the input and its purpose.

<label for="address">Address</label>
<input id="address" type="checkbox" checked name="address">

Or wrap the control so the label and input stay together:

<label>
    Address
    <input type="checkbox" checked name="address">
</label>
<div>
    Address
    <input type="checkbox" checked name="address">
</div>

Icon-only buttons

A hamburger that is only three lines has no name. A screen reader may say “button” and nothing else. Name the control, and hide the drawing from assistive technology.

<button type="button" aria-label="Open menu">
    <span class="hamburger" aria-hidden="true"></span>
</button>
<button type="button">
    <span class="hamburger"></span>
</button>

Note: aria-hidden="true" keeps the bars out of the accessibility tree. The name lives on the button, e.g. aria-label="Open menu" or visible text like “Menu”.
