Role

role sets what an element is in the accessibility tree. A screen reader uses that type when it announces the control: button, radio, switch.

Roles that come with the element

Many HTML elements already have a role. The browser adds it to the accessibility tree from the tag, with no role attribute.

<button>
button
<a href>
link
<nav>
navigation
<input type="checkbox">
checkbox
<h1> to <h6>
heading

This button has no role attribute. A screen reader still says “Order a drink, button”.

Note: Use the HTML element when one already matches the widget. Add role when you are building a control the tags do not cover.

Setting a role

These drink options are plain elements. On their own, a screen reader hears the words and no choice. role="radiogroup" marks the set. role="radio" marks each option. aria-checked is true or false.

Note: In a real form, use <input type="radio">. This demo uses role so you can see it. The role does not put an option in the Tab order or check it when you press an arrow. tabindex and the script do that. Arrow keys move the selection.

A screen reader can say “Water, selected, radio” inside “Drink options, radio group”.

Replacing a role

A <button> starts life as a button. role="switch" replaces that type with switch. aria-checked stores whether it is on.

Not checked

<button>Enable</button>

The screen reader would read that as “Enable, button”.

<button role="switch" aria-checked="true">
    Enable
</button>

With the role replaced, a screen reader says “Enable, switch, checked” when aria-checked is true.

Note: The role updates the accessibility tree. You still style the control and handle the keyboard yourself.
